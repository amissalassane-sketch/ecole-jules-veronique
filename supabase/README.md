# EBJV Supabase setup

This repository contains a **foundation**, not a configured Supabase project. Apply `migrations/20260825_admissions_foundation.sql` in the Supabase SQL editor or with the Supabase CLI before enabling the public registration form.

## Required external configuration

1. Create a Supabase project and add its URL plus publishable anon key to local `.env` from `.env.example`.
2. In **Auth → Providers**, enable **Anonymous Sign-Ins**. The public form uses an anonymous authenticated session only to bind a draft and its uploads to one browser session; it does not grant application reads.
3. Create the first administrator in **Auth → Users** with a password of at least 8 characters (T-001 acceptance criterion), then execute the seed statement at the end of the migration with that Auth UUID.
4. Confirm the `application-documents` bucket is private. Never use `getPublicUrl()` for this bucket.

## Security model

- Public applicants receive an anonymous Auth identity; RLS does not allow them to select/list applications or document metadata.
- Application UUIDs are generated by PostgreSQL through an RPC and are not human-facing references or matricules.
- Applicants may upload/delete only their own **draft** documents under a strict `{application-id}/{kind}/{file-id}.{extension}` path.
- Administrators authenticate with Supabase Auth and are authorized only when their Auth UUID is in `admin_users`.
- Admin document viewing uses a short-lived signed URL generated after RLS-authorized Storage access.
- No service-role key is required or permitted in frontend code.

## F-003

The TDR and annex require a unique matricule in a predefined format but do not define that format. No matricule generator is included. Obtain written school approval for the format before adding a database-side generator.
